# 双色球智能预测分析系统

> 一款福彩双色球预测系统，基于历史开奖数据，用 AI 分析长期、中期、短期规律，预测下一期开奖数据。

用 **大模型（LLM）+ 统计方法** 分析双色球历史开奖数据，寻找长/中/短期规律，
并对每条规律做 **样本外回测与显著性检验**，最终由「统计基线模型 + LLM 推理」集成输出
**带置信度与推理依据**的下期候选号码。

> ⚠️ **诚实边界**：双色球每期开奖是独立随机事件。本系统的样本外回测结果（见下文）实证了
> **不存在稳定、显著优于随机的规律**（全部规律经多重检验校正后 p 值均未通过 0.05 阈值）。
> 因此本系统的价值不在于"提高命中率"，而在于：
> 1. 用可证伪的方式量化各种流行"规律"的真实证据强度；
> 2. 在约束下生成结构均衡的候选组合与可解释的推理理由；
> 3. 用与随机基线的对照评估，诚实地展示"投注期望回报为负"。
>
> 系统输出仅供研究参考，不构成中奖概率与投注建议。**理性购彩，量力而行。**

## 🚀 v2.2.0 升级概要（V6 阶段有效性 + 多维度规律 + LLM 规律工坊）

**用户口径**：①「分析获取的规律不太多」②「近期规律都不生效」③ 希望从多个维度找规律、
让大模型在找规律中发挥更多作用、并识别规律的**阶段有效性**。

先做诊断再动手（完整数据见 [`docs/V6_REGIME_DIAGNOSIS.md`](docs/V6_REGIME_DIAGNOSIS.md)），
三条根因全部来自本机 3515 期真实数据：

| 现象 | 根因（实测） |
|---|---|
| 规律不多 | 规律库是 **47 条手写规则**，只覆盖号码/遗漏/结构三类；日期维度、跨期联动、形态序列、时间尺度全部缺失 |
| 近期不生效 | 检验里**没有时间维度**：全历史混算成一个 `n=3215, margin=-0.004`，看不出「曾经有效、何时失效」。实测「近 30 期热号」在 2023 年单年显著（t=−2.99, p=0.003），2024/2025/2026 全部回归 0 —— 这就是「不生效」的真实形态 |
| 回测虚高 | 用**今天的阈值**判 2005 年的每一期（事后分位）。实测全样本口径比 as-of 口径平均每期多「命中」**0.031 个红球**，而 3515 期下的最小可检出效应只有 0.041 个/期 |
| AI 参与度低 | LLM 只看到战绩表 + 最近 12 期；其产出的规律走不通验证通道（非结构类假说 A/B 恒 Δ=0）；结构类 A/B 也是**同池重排**造成的恒零伪影（三条规则实测 Δ=+0.012/−0.005/−0.020） |

**交付（四块）**：

1. **`lottery/regime.py` 阶段有效性层**
   - 9 个阶段（2003-2008 / 2009-2012 / 2013-2016 / 2017-2020 / 2021-2022 / 2023 / 2024 / 2025 / 2026，近年更细）
   - 逐阶段显著性（t / 二项）+ **BH 校正** + 每阶段最小可检出效应（MDE）+ 近 150 期加权检验
   - 状态机：`persistent` 持续 / `emerging` 新兴（只在一个阶段显著→**禁止出号**）/
     `fading` 衰减 / `stale` 陈旧（最近一次显著距今 >300 期）/ `flipped` 方向反转 / `reversed` 已失效 / `noise` 未检出
   - 校准实测：纯随机数据下假阳性率 **0.050**（名义 0.05）；检测力：单一年份 +0.06 的效应检出率 81%
2. **`lottery/discovery.py` 多维度规律发现**
   - **20 个维度族 × 91 组参数**：热冷（6 个时间尺度）、遗漏、回补比、连出、重号、隔期复出、邻号（±1/±2/±3）、
     同尾、区间回补、派生集合（除 3/±差/倍数）、号码对共现、开奖日（星期几）、形态条件延续（奇偶/大小/0路/和值尾/跨度）、
     蓝球 6 类；支持**跨维度交集/并集**组合
   - **严格 as-of**：第 t 期只用 `draws[:t]`；增量 `ScanContext`（滑窗计数 O(1) 摊销），单次全量扫描约 5 秒
   - 扫描必报**搜索成本**：已测组合数与「纯随机预期假阳性数」（91×0.05≈4.6）
   - 实测结论：`扫描 91 组 · 预期假阳性 4.6 个 · 无任何维度达到校正显著（最优 BH p=1.000）`
3. **`lottery/llm_lab.py` LLM 规律工坊**
   - 输入：全历史**分阶段序列**（每阶段红球最热/最冷 5、蓝球最热 3、和值均值与标准差、奇数均值）、维度表、
     as-of 候选（含校正后 p）、搜索成本提示、当前状态快照
   - 三轮：提规律 → **自我质疑**（"这会不会只是 91 次搜索里的假阳性?"）→ 据质疑修订
   - 每条规律**必须映射到维度表档位**并做 as-of 回放；映射不到 → `unmappable`，明确"不可验证"，
     绝不算作验证通过
4. **A/B 验证修复 + 前端工作台**
   - 结构类 A/B 两臂改为**独立采样**（各 n_tickets 注）+ Wilcoxon 配对检验；对照组从 `uniform` 改为**实际部署基线**
   - 新动作 `prefer_red_filter` / `prefer_blue_filter`：把维度筛选条件真正接进出号偏置（as-of 求值）
   - 前端「评估报告 → ⏳ 规律时效」：状态计数横幅（陈旧/衰减/持续 + 量化回答"近期不生效"）、
     阶段 × 规律热力图（★=校正后显著）、维度空间扫描、LLM 工坊、**检索式核验**（选维度+档位即看阶段画像）

## 🚀 v2.1.0 升级概要（V5 自进化系统）

**用户口径**：准确性 = 基于历史数据查找规律特点 → 用于实战 → **通过实战结果对比**。
本文档与系统均按此口径组织：所有结论都是「哪个方法在 N 期实战中更好/更差、差多少、是否显著」。

**交付四段闭环**（这是本次的核心，也是系统第一次具备自我完善能力）：

```
历史数据 → 战斗回放逐期验证 → LLM 提炼规律 → A/B 实战验证 → 裁决 → 用已验证规律预测
```

1. **`lottery/battle.py` 方法级 walk-forward 战斗回放**
   - 对每个出号方法在「只用 `draws[:t]`」条件下逐期出号，与第 t 期真实开奖核对
   - 红球 Wilcoxon 符号秩 + 蓝球 McNemar + Fisher 合并 + **Bonferroni/BH 多重检验校正**
   - 严格防未来信息泄漏（有双向测试守着）；`ml`/`llm` 无法回放则如实标注 `replayable: False`
2. **`lottery/hypothesis.py` LLM 规律提炼 + 假说库**
   - 先确定性统计挖掘（频率偏移/遗漏回补/重号/邻号/结构指标/方法趋势），
     再把战绩喂给 LLM 提出**可实战验证**的新假说
   - LLM 不可用/超时/解析失败一律优雅降级为纯统计假说，绝不抛异常
   - 假说带生命周期 `proposed → validated/rejected/retired`，按 `statement` 去重并累加 attempts
3. **`lottery/evolution.py` 进化闭环**
   - **只消费 `validated` 假说**：未经验证的规律不得影响真实出号（有测试守着）
   - `verify_hypothesis_ab()`：同批历史同 seed 的配对 A/B 回放，给出 Δ红球/Δ蓝球
   - `predict_with_evolution()`：用已验证规律出号；**空库时如实说明「输出等同基线」**
4. **每期自动进化**：调度器在开奖 → 抓取 → 在线对照之后、生成预测之前自动跑一轮
   （挖掘 → 注册 → 对每条 proposed 做 A/B 验证 → 裁决）；进化失败**不影响**当期预测生成

**实测数字（3515 期全量回放，3215 期可评估 × 10 注）**：

| 方法 | 红球均值 | 蓝球命中率 | ≥五等奖率 |
|---|---|---|---|
| stat:freq | 1.0951 | 6.24% | 6.67% |
| blue_coverage | 1.0951 | 6.32% | 6.76% |
| uniform | 1.0926 | 6.30% | 6.69% |
| stat:bayes | 1.0864 | 6.33% | 6.75% |

- **11 组配对：未校正显著 3 组 → 多重检验校正后仅 1 组**。校正真实拦下了假阳性。
- `uniform` 的 ROI +203.9% 是**单期离群值**（2022128 期 1 注全中 6 红 = 二等奖 ¥180,000）。
  界面因此**同时给出剔除一二等奖的稳健口径 `roi_ex_top`**（各方法 −75%~−78%）。
- **9 条假说各做 515 期配对 A/B**：Δ红球全部落在 ±0.015 内 →
  裁决 **0 validated / 0 rejected / 9 unchanged**。目前没有任何规律达到显著，

## 🚀 v2.0.0 升级概要（V4 诚实口径重构）

**背景**：用户报告系统「准确性过低」，要求分析可提升准确性的方法、必要时推倒核心算法重做。
本次没有去调参追逐命中率，而是先做量化诊断——结论改变了整个改造方向。

**诊断（本机 3514 期真实开奖数据，详见 [`docs/V4_ACCURACY_DIAGNOSIS.md`](docs/V4_ACCURACY_DIAGNOSIS.md)）**：

- 红球频率卡方 **45.18**（df=32, p=0.061）、蓝球卡方 **8.84**（df=15, p=0.886）
  → 开奖分布与**均匀随机不可区分**；
- 7 类「规律」策略样本外检验：热号/冷号/遗漏/重号 t 值几乎全部 |t|<1；
  唯一冒尖的热号 W=100（+3.08%, t=+2.18, 未校正 p=0.029）经多重检验校正后
  **p=0.102，不显著**——这是几十种策略里搜索出来的**预期假阳性**；
- 系统累计评估样本仅 **25 注**，而检出 +10% 命中提升需约 **261 注**、+5% 需约 **1046 注**。

**结论：单注命中率在数学上不可提高**（红球期望恒为 6×6/33=1.0909/注，蓝球恒为 1/16）。
在「预测号码」这个方向上继续投入算力不可能改善"准确性"。本次改为做两件真正可做的事：

1. **修掉真实算法缺陷**——它们才是"准确率观感差"的直接原因；
2. **把目标改为唯一在数学上可优化的部分**：固定预算下的**组合覆盖**，
   并让评估口径**不可自欺**。

**交付内容**：

- **V4-A 严格统计检验层**（`lottery/rigor.py`）：随机性体检（9 项检验）、
  多重检验校正（Bonferroni + BH-FDR）、最小可检出效应反推、walk-forward 信号评估。
  任何策略必须先**通过校正**才允许被称为「有效」。
- **V4-B 修掉融合权重的样本内过拟合**：原 `_brier_blend` 用最近 50 期做**样本内** Brier，
  再用 `1/brier` **无界倒数放大**（样本内 brier=0.001 时权重可达均匀模型的 **148.8 倍**）。
  现改为严格 **walk-forward 样本外** Brier → softmax（带温度）→ 硬上限
  `MAX_MODEL_WEIGHT=0.6` → 权重收缩 `WEIGHT_SHRINKAGE=0.5`；
  无法回放的方法不参与定权，如实标注 `fixed-fallback`。
- **V4-C 重建核心目标为覆盖优化 + 奖金期望**：
  - `blue_coverage_plan()`：n 注的蓝球**互不相同**，把「至少中 1 蓝」的概率
    从 `1-(15/16)^n` 提升到 `min(n,16)/16` —— n=5 时 **27.58%→31.25%**、
    n=10 时 **47.55%→62.50%**、n=16 时 **100%**。这是本系统唯一真实可得的改进。
  - `portfolio_expected_value()`：按真实奖级规则计算期望奖金；一/二等奖为浮动奖，
    以显式常量假设并在返回值标注 `jackpot_assumption`。
  - 修掉 `_apply_blue_mode` 的**在噪声上做决策**：30 期样本根本无法区分 4.5% 与 6.25%，
    回退门槛改为统计反推的最小显著样本量（**735 期**）。
- **V4-D 诚实口径落到界面**：新增 `/api/rigor/randomness`、`/api/rigor/signal`、
  `/api/portfolio/expected-value`（缺 `rigor` 模块时优雅降级 503，不影响启动）；
  前端所有比率指标**必须带样本量**，样本不足时显示「样本不足，不构成结论」
  而不是一个看起来像能力的百分比；新增「🎲 随机性检验」卡，直接回答
  「为什么准确率上不去」，并给出当前样本量下的最小可检出提升。

**必须同时说清的两条诚实边界**：

1. 覆盖优化提高的是**中奖频率**，**不是**期望收益——六等奖 EV 比恒为 `5/32=0.15625`，
   与注数无关；覆盖满 16 个蓝球确实「必中」，但花 ¥32 只换回 ¥5，**净亏 ¥27**。
2. 单注完整期望回报约 **¥0.9135** / 成本 ¥2.00 → **返还率 45.67%**，
   即每投注 ¥100 期望亏损约 **¥54.33**。这是数学事实，任何算法都无法改变。

> 因此本系统现在的定位是**诚实的统计检验与可视化工具**，不是预测器。
> 若目标是「提高中奖率」——那在数学上不可达；若目标是「同等预算下覆盖更多可能性」，
> 蓝球去重覆盖是真实有效的，但请理解 EV 不变。

  逐触发期计算期望与边际、Wilson 置信区间，t 检验 + Benjamini-Hochberg 多重检验校正，规律分级 A/B/C
  （显著/弱信号/不通过），显著但方向相反者标记"证伪"；另有自动挖掘管道持续产出候选规律。
- **预测引擎**：4 个统计基线模型（频率加权、遗漏回补、马尔可夫转移、贝叶斯更新）+ **M2 ML 概率模型**
  （GBDT + 随机森林，33 维红球 / 16 维蓝球独立建模）+ **U2 蓝球专用模型** → 滚动 **Brier 加权融合**
  → 硬约束（和值分位、三区比、奇偶分布、号码去重）+ 概率校准 + **LLM 组合结构优化**（观察 → 选号，
  蓝球交由专用模型），最终输出候选注 + 置信度 + 推理理由。
  **U7**：LLM 推理时注数**以大模型实际产出为准，不补齐**（`LOTT_LLM_ONLY_OUTPUT=0` 可关闭）；
  另支持蓝球复式 / 红胆拖投注模式与 `coverage` 组合覆盖优化（`/api/eval/coverage` 离线对照）。
- **U3 方法自适应降权**：连续多期命中低于随机基线的方法在 production 模式自动降权或移出候选池，
  research 模式保留完整方法对比（诚实保留，不删除任何方法）。
- **评估闭环**：离线 walk-forward 引擎回测与 **ML 滚动评估**（对照均匀随机基线，输出 Brier /
  log-loss / 校准曲线 / ECE / paired 显著性检验）；开奖后在线对照入库。
- **部署友好**：Python 标准栈，FastAPI 直接托管零构建单页前端（ECharts CDN），
  单进程运行，低资源占用；可选 Docker / 开奖日自动调度。

## 安装部署（新手向导）

> 二选一：**方式一 Docker（推荐，最省事）** 或 **方式二 本地 Python**。
> 两种方式都**可以不配置 LLM 直接运行**（自动降级为纯统计模型），配了 LLM 才有 AI 推理选号。

### 第 0 步：准备

- 一台机器：本地电脑或 VPS 都行，**要求很低**（1 核 CPU / 512MB 内存即可）；
- 可选：一个 OpenAI 兼容的 LLM 服务（DeepSeek / 智谱 / 通义等任意一家），拿到它的 **API 地址 + Key + 模型名**。

### 方式一：Docker Compose（推荐，新手最省事）

```bash
# 1) 安装 Docker（已装可跳过；Ubuntu/Debian 一条命令）

cd ssqyuce

# 3) 配置 LLM（可选：不配置也能跑，只是没有 AI 推理）

docker compose up -d --build

# 5) 打开浏览器
#    本机:  http://localhost:18000      服务器: http://服务器IP:18000
curl http://localhost:18000/api/health   # 返回 {"status":"ok",...} 即成功
```

> **密钥与地址不入库**：所有 LLM URL / Key 只从环境变量或 `.env` 读取（模板见

| 变量 | 默认 | 说明 |
|---|---|---|
| `LOTT_LLM_BASE_URL` | （必填） | OpenAI 兼容 LLM 端点（DeepSeek/智谱/通义等均可） |
| `LOTT_LLM_API_KEY` | （必填） | LLM Key |
| `LOTT_LLM_MODEL` | `minimax-m3` | 主模型 |
| `LOTT_LLM_MODEL_LIST` | 空 | 同一通道多模型，逗号分隔，采样时按模型轮转 |
| `LOTT_LLM_EXTRA_MODELS` | 空 | 附加独立通道，JSON 数组 `[{"name","base_url","api_key","model"}]` |

| `LOTT_LLM_MAX_TOKENS` | `32000` | 推理型模型的输出预算上限：检测到「只返回 reasoning、正文为空」时一次抬到该值重试；设 `0` 关闭自适应 |
| `LOTT_LLM_LONG_TIMEOUT` | `180` | 大输出预算单次调用的宽松超时（秒）；大预算单次就要 30~120s，沿用 `LOTT_LLM_TIMEOUT=60` 会先被判超时 |
| `LOTT_LLM_DISABLED` | `0` | `1` = 关闭 LLM，仅统计模型 |
| `LOTT_LLM_ONLY_OUTPUT` | `1` | `1`=LLM 推理时以大模型**实际产出注数**为准、不补齐；`0`=恢复旧的混选补齐 |
| `LOTT_N_TICKETS` | `10` | 输出注数（LLM-only 模式下为**上限**，不保证补满） |
| `LOTT_BET_MODE` | `single` | 投注模式：`single` / `blue_compound`（蓝球复式）/ `dan_tuo`（红胆拖） |

| `PORT` | `18000` | Web 服务端口（Docker/环境变量） |
| `LOTT_DB` | `data/ssq.db` | 数据库路径 |
| `LOTT_TOKEN` | 空 | 配置后所有 `/api/*` 要求 `Authorization: Bearer <值>`；留空兼容开放访问 |
| `LOTT_BACKUP_DATA_URL` | 空 | 可选备用开奖源；只读对账，不覆盖主库 |
| `LOTT_METHODS` | 空 | M4.2 方法开关；空值=全部启用，支持族名/全名与 `-` 拒绝列表 |

## 版本记录

### v2.1.0（V5：自进化系统 —— 战斗回放 + LLM 规律提炼 + A/B 验证闭环，2026-10）

> 用户口径：准确性 = 基于历史数据查找规律特点 → 用于实战 → **通过实战结果对比**。
> 本节所有结论均按此口径给出（哪个方法在 N 期实战中更好/更差、差多少、是否显著）。

**新增三个模块 + 三个端点 + 每期自动进化**：

- `lottery/battle.py`（49 测试）：方法级 walk-forward 战斗回放。
  `replay_method` / `replay_all` / `compare_methods` / `battle_report`；
  红球 Wilcoxon、蓝球 McNemar、Fisher 合并、Bonferroni 与 BH(FDR) 校正；
  严格只用 `draws[:t]`（双向泄漏测试守着）；`ml`/`llm` 标 `replayable: False` 不伪造。
- `lottery/hypothesis.py`（46 测试）：LLM 规律提炼 + 假说库。
  确定性统计挖掘（7~9 条规律族）+ LLM 提炼可验证假说（实测 LLM 产出 5 条含具体 action 与证据）；
  LLM 失败/超时/结构非法一律降级；假说库 `data/hypotheses.json`（运行时状态，已 gitignore）。
- `lottery/evolution.py`（32 测试）：进化闭环。`apply_hypotheses`（**只消费 validated**）、
  `apply_structure_rules`（重号/邻号/隔期复出/奇偶/三区，只重排不增删）、
  `verify_hypothesis_ab`（配对 A/B 实战验证）、`predict_with_evolution`（规律驱动预测）。
- `lottery/api_app.py`：新增 `_evolution_step()` 接入调度器 ——
  每期开奖后自动「挖掘 → 注册 → A/B 验证 → 裁决」；失败不影响当期预测生成。
  端点 `/api/battle/report`、`/api/evolution/status`、`/api/evolution/run`（缺模块降级 503）。
- 前端：「评估报告 → 🧬 实战战绩」子页（进化总览 / 战绩榜 / 两两对比 / 规律库 / 进化操作）。

**修掉的三个集成缺陷**（都是「看起来能跑、实际断链」）：
1. **71% 挖掘结果被静默丢弃**：挖掘端产出 `prefer_structure`，而白名单不含它 →
   7 条里 5 条被拒，闭环形同虚设。已纳入白名单并实现 `apply_structure_rules`（2/7 → 7/7）。
2. **假说永远停在 proposed**：`evolve_once` 只挖掘+注册，**没有任何环节送去做 A/B 验证**，
   进化成了只挖不验的空转。新增 `_evolution_step` 补上验证与裁决。
3. `evolve_once` 把假说库 dict 当假说 → AttributeError；`_registry_path` 传 str 时
   `path.parent` 崩。均已修并加回归测试。

**重要发现（值得记住）**：`uniform` 的 ROI +203.9% 来自**单期离群值**
（2022128 期 1 注全中 6 红 = 二等奖 ¥180,000）。单个浮动奖即可主导 ROI，
故新增剔除一二等奖的稳健口径 `roi_ex_top`，前端两口径并排展示。

**测试**：全量 **356 → 380 passed**；`?v=` → 20261015.2；APP_VERSION → 2.1.0。

### v2.0.0（V4：诚实口径重构 —— 覆盖优化 + 严格样本外评估，2026-10）

> 触发原因：用户实报「准确性过低」，要求分析可提升准确性的方法、必要时推倒核心算法重做。
> **本次不是一次"提升命中率"的迭代，而是一次方向纠正**：先量化诊断证明命中率不可提升，

**诊断结论（本机 3514 期）**：开奖分布与均匀随机不可区分（红球卡方 45.18/p=0.061，
蓝球 8.84/p=0.886）；7 类规律策略在多重检验校正后**无一显著**（最强为热号 W=100，
未校正 p=0.029 → 校正后 p=0.102）。红球命中期望恒为 1.0909/注。

**A. 新增 `lottery/rigor.py`（严格统计检验层）**

- `randomness_report()`：9 项随机性检验（红/蓝频率卡方、和值拟合、奇偶、三区、连号、
  同尾、重号、蓝重复），各项含 statistic/df/p_value/verdict，顶层给出综合 `verdict`
  与 `min_detectable_effect`（当前样本量下能检出的最小提升）
- `strategy_significance()` / `strategy_significance_multi()`：t 检验 + 符号检验 +
  **Bonferroni 与 BH-FDR 多重检验校正**；单策略无法做 BH 时 `bh_p=None` 并标注
  `not-applicable-single-p`，**绝不**用 `min()` 把不可计算值当成更优值选中
- `min_sample_size()` / `evaluate_signal()`：效应量反推样本量；walk-forward 信号评估
- 检验**有功效**：注入偏置必判 deviation，真随机数据不得误报（双向自证）

**B. 修掉 `_brier_blend` 的样本内过拟合（`lottery/engine.py`）**

- 原实现：最近 50 期**样本内** Brier → `1/brier` **无界倒数放大**
  （brier=0.001 时权重达均匀模型的 148.8 倍），且无权重上限
- 现实现：**严格 walk-forward 样本外** Brier（用 `draws[:t]` 重建概率）
  → softmax（温度 0.05/0.02）→ 硬上限 `MAX_MODEL_WEIGHT=0.6`
  → 权重收缩 `WEIGHT_SHRINKAGE=0.5`
- 无法回放的方法（ml/外部注入/LLM）**不参与定权**，以等权参与并标注 `weight_source="fixed-fallback"`
- 实测：同一 10× Brier 差下，旧逻辑给 10× 权重比，新逻辑仅 1.50×

**C. 重建核心目标为覆盖优化 + 奖金期望（`lottery/engine.py`）**
